# Group7 TicTacToang — Project Summary

> Single-file reference for prompting AI tools about this codebase.
> Keep alongside the repo; paste into any AI conversation as context.

## 1. What it is

A full-stack web game implementing **Gomoku (5-in-a-row Tic Tac Toe)** with
local, online multiplayer, and AI opponents. Built for the RMIT Full-Stack
Development 2026A course by Group7.

Repository: https://github.com/RMIT-Full-Stack-Development-2026A/Group7
Default branch: `main`

## 2. Tech stack

### Frontend (`frontend/`)
- React 19 + Vite 8
- React Router v7
- TailwindCSS 4 (+ Bootstrap icons, lucide-react icons)
- socket.io-client 4 (realtime gameroom + game)
- ESLint 9 (with `react-hooks/set-state-in-effect` enforced)

### Backend (`backend/`)
- Node + Express 4
- Mongoose 7 / MongoDB Atlas
- socket.io 4
- JWT auth (`jsonwebtoken` + `bcryptjs`)
- Nodemailer (SMTP — Gmail App Password)
- PayPal Orders v2 (sandbox/live, guest card checkout enabled)

### Deployment
- `render.yaml` defines a Render web service (backend) + static site (frontend)
- Backend health: `GET /api/health`
- CORS auto-allows `*.onrender.com`, `*.vercel.app`, `*.netlify.app`,
  `*.railway.app`, `*.fly.dev`, all localhost / private network origins

## 6. Real-time (socket.io)

Server: `backend/src/socket/gameroom.socket.js`. Events used in rooms:
- `join-room` / `leave-room`
- `room-updated`, `room-closed-by-admin`, `room-deleted`
- `chat-message`
- `room-invite-approval-request` / `room-invite-approval-response`
  (non-host members ask host to approve invites)
- `game-started`
- `game-move` (client → server), `game-move-applied` (server → client)
- `game-action` with `action: 'player-resigned'`

## 7. Game logic

- Board: 10x10 or 15x15. Win = 5-in-a-row any direction.
- AI difficulties: `easy`, `medium`, `hard` — see
  `frontend/src/shared/utils/ai-moves.utils.js` (and matching backend
  `backend/src/shared/utils/game.utils.js` for server-side AI).
- Local multiplayer supports 2–4 players (mix of humans + AI) on one device.
- Online multiplayer: room host controls slots; non-host can request to add
  friends via host-approval flow.
- Game start payload picks `/vs-computer` (1v1 vs AI) vs `/vs-friend` (any
  other config) based on room composition.
- Algebraic notation in MatchReplay axes (a–o cols, chess-style row numbers).

## 8. Auth + access control

- JWT (`Authorization: Bearer ...`) issued by `auth.service`.
- Middleware:
  - `authenticate` — require token
  - `optionalAuthenticate` — attach if present
  - `requireActiveAccount` — block `accountStatus: 'inactive'` (suspended)
  - `requireRole('admin')` — gate admin routes
- Admins can suspend accounts. Suspended users see "Your account are in
  suspansion, cannot use this feature" on gated tabs. Friends tab stays open.

## 9. Premium gating

- `isPremiumIdentity()` checks profile flag set by Subscription page after
  PayPal capture.
- Match Replay is premium-only — UI gates the replay link on the match
  history card; if a non-premium user reaches `/match-replay/:gameId`
  directly, they're redirected to `/match-history`.
- Backend `/api/games/:gameId/replay` does NOT currently enforce premium
  (UI is the only gate — flag this if hardening is needed).

## 10. Module conventions

- Each frontend page splits into:
  - `pages/X.jsx` — thin composition, JSX only
  - `hooks/useX.js` — state, effects, handlers
  - `logic/x.utils.js` — pure helpers
  - `components/X/*.jsx` — subcomponents
- Each backend module has the same shape:
  - `x.routes.js` → `x.controller.js` → `x.service.js` → `x.repository.js`
  - DTOs in `x.dto.js`, validators in `x.validator.js`
  - Helpers in `x.<feature>.helpers.js` when service grows
- **300-line cap**: every `.js` / `.jsx` / `.css` file is ≤300 lines. When
  a file grows beyond, split into a hook / helper / subcomponent rather than
  inlining more code.
- Co-located CSS, often imported via a parent file:
  - `theme.css` → `theme.base.css`, `theme.controls.css`, `theme.directory.css`,
    `theme.light-main.css`, `theme.light-history.css`, `theme.light-rooms.css`
  - `gameroom.css` → `gameroom.layout/players/chat/friends/light.css`
  - `GameBoard.css` → `GameBoard.base/tiles/styles/turn-order.css`

## 14. Deployment (Render)

`render.yaml` declares:
- `tictactoang-backend` (web, node) — `rootDir: backend`, healthCheck
  `/api/health`. Env vars are placeholders (set in Render dashboard);
  `JWT_SECRET` uses `generateValue: true`.
- `tictactoang-frontend` (static) — `rootDir: frontend`, build `npm install &&
  npm run build`, publish `dist`, SPA rewrite of all routes to `/index.html`.

After deploy, the frontend can derive `VITE_API_BASE_URL` / `VITE_SOCKET_BASE_URL`
from `VITE_BACKEND_ORIGIN`. In Render, `render.yaml` wires `VITE_BACKEND_ORIGIN`
from the backend service's external URL. Add custom frontend domains to the
backend's `CORS_ORIGIN` when not using the default onrender.com host.

## 15. Things an AI assistant should know

- **Don't grow files past 300 lines.** Extract a hook, a helper, or a
  subcomponent instead. Existing splits (e.g. `useGameroomPage` ⇒
  `useGameroomActions` + `useGameroomInvites`, `useGameBoardEffects` ⇒
  `useGameBoardRemoteEffects` + `useGameBoardLocalEffects`) follow this rule.
- **Lint rule `react-hooks/set-state-in-effect`** is enforced. To call a
  setter inside an effect body, wrap it in `queueMicrotask(() => setX(...))`.
- **Pure helpers go in `logic/*.utils.js`** (frontend) or
  `*.helpers.js` (backend). Hooks orchestrate state + side effects only.
- **Routes are centralized** in `frontend/src/router/routes.config.js` — never
  hardcode path strings in components; import `ROUTES`.
- **Frontend API base URL is dynamic** — don't import a literal localhost
  URL; always call `getApiBaseUrl()` / `getSocketBaseUrl()`.
- **Avatar URLs** go through `resolveAvatarUrl()` (handles AI placeholder,
  data URLs, and stored paths).
- **Marker names** are restricted by `isSafeMarker()` / `SAFE_MARKER_OPTIONS`
  — don't accept arbitrary strings from the client.
- **Identity normalization**: `getStoredAuthIdentity()` for synchronous reads,
  `resolveAuthIdentity()` for async fresh reads.
- **Suspended accounts**: when adding a new feature accessible from the main
  menu, check `SUSPENDED_ALLOWED_TABS` in `mainMenu.utils.js` and either add
  it to the allowlist or surface the suspension message.

## 16. Known gaps / follow-ups

- `/api/games/:gameId/replay` is not premium-gated server-side — the UI
  redirect is the only barrier.
- Frontend bundle is ~500kB minified (one chunk). Consider dynamic imports
  for `MatchReplay` / `AdminPanel` if size becomes a concern.
- `.env` files are committed to the repo per team's decision (see commit
  `673da9f`); secrets should be rotated if the repo ever goes public.
